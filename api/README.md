# Ornipedia API

## Quick start

Install requirements

```bash
pip install -r requirements/requirements.txt
```

Create (or update) the database schema, see [Database migrations](#database-migrations):

```bash
alembic upgrade head
```

Start the API using uvicorn:

```bash
uvicorn src.main:app [--reload]
```

The interactive documentation is then available on <http://localhost:8000/docs>.

## Configuration

The default settings are defined in [src/settings.py](src/settings.py). They can be overridden:

1. by a `src/settings_local.py` file (ignored by git, generated by the Ansible deployment), then
2. by the following environment variables:

| Variable | Description | Default |
| --- | --- | --- |
| `ORNIPEDIA_PSQL_USER` | PostgreSQL user | `postgres` |
| `ORNIPEDIA_PSQL_PASSWORD` | PostgreSQL password | `mysecretpassword` |
| `ORNIPEDIA_PSQL_HOST` | PostgreSQL host | `127.0.0.1` |
| `ORNIPEDIA_PSQL_PORT` | PostgreSQL port | `5432` |
| `ORNIPEDIA_PSQL_DB` | PostgreSQL database | `ornipedia` |
| `ORNIPEDIA_DB_URL` | Full SQLAlchemy database URL, takes precedence over the `PSQL_*` settings | built from the `PSQL_*` settings |
| `ORNIPEDIA_DB_DEBUG` | Log the SQL queries (`true`/`false`) | `false` |
| `ORNIPEDIA_ALLOWED_ORIGINS` | Comma separated list of origins allowed by CORS | none |
| `ORNIPEDIA_IMAGE_FOLDER` | Folder containing the images | `/path/to/the/image/folder` |
| `ORNIPEDIA_THUMBNAIL_FOLDER` | Folder where the resized images (`GET /images/{id}?width=320\|640\|1280`) are cached | `<system temp dir>/ornipedia-thumbnails` |
| `ORNIPEDIA_ADMIN_PASSWORD` | Password of the administration (`/admin` page and `/admin/*` endpoints), the administration is disabled when empty | empty |

## Administration

The `/admin` page of the front adds birds and photos, and deletes photos from the gallery. It uses the `/admin/*` endpoints, protected by `ADMIN_PASSWORD` (sent as `Authorization: Bearer <password>`). Uploaded photos are saved in `IMAGE_FOLDER` under random names.

Photos can be imported from [Wikimedia Commons](https://commons.wikimedia.org): the API searches the files (`GET /admin/commons/search`) and imports the chosen ones (`POST /admin/birds/{id}/commons`), fetching their author and license from Commons itself. The server must be able to reach `commons.wikimedia.org` and `upload.wikimedia.org`; the requests are identified by `COMMONS_USER_AGENT`, as required by the [Wikimedia User-Agent policy](https://meta.wikimedia.org/wiki/User-Agent_policy).

Use a long random password (e.g. `python -c "import secrets; print(secrets.token_urlsafe(24))"`): each failed attempt is only slowed down by one second.

## Database migrations

The database schema is managed with [Alembic](https://alembic.sqlalchemy.org/), the migrations are located in [migrations/versions](migrations/versions). The database URL is read from the settings above.

Apply all the migrations:

```bash
alembic upgrade head
```

> [!IMPORTANT]
> For a database created before Alembic was introduced, first mark the initial migration as already applied, then upgrade:
>
> ```bash
> alembic stamp 0001
> alembic upgrade head
> ```

After modifying the models in [src/database/db_models.py](src/database/db_models.py), generate a new migration (and review it!):

```bash
alembic revision --autogenerate -m "short description"
```

The CI checks that the migrations match the models with `alembic check`.

## Run tests

Install dev requirements

```bash
pip install -r requirements/dev-requirements.txt
```

Run the tests with `pytest` (they use an in-memory SQLite database, no PostgreSQL server is needed)

```bash
pytest tests/
```

## Test coverage

Run tests with coverage

```bash
coverage run -m pytest tests/
```

Show coverage report

```bash
coverage report
```

Generate HTML coverage report (coverage report is generated in [htmlcov/index.html](htmlcov/index.html))

```bash
coverage html
```
